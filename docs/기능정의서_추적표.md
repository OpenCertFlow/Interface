# 기능정의서 ↔ 구현 추적표 (Traceability Matrix)

> `인증메이커스_기능정의서_요구사항정의서_v0.xlsx`의 기능 ID(F-XXX)를 실제 구현 근거(엔드포인트·클래스·마이그레이션·이슈)에 매핑한다.
> **목적**: 심사 때 "정의서대로 구현되었는가"를 근거로 증명하기 위함. 값은 실제 코드 기준이며, 없는 것을 있다고 적지 않는다(불변식 6).

## 상태 표기

| 표기 | 뜻 |
| --- | --- |
| ✅ | 백엔드/AI워커 기준 구현 완료(엔드포인트·로직·테스트 존재) |
| 🟡 | 부분 구현 — 핵심 로직·API는 있으나 일부(플로우·승인·UI 연동)가 남음 |
| ⬜ | 미구현 — 주로 Android/Web **UI**(다른 팀원 담당) 또는 알림·감사로그 등 별도 과제 |

> **UI 범위 주의**: 이 저장소는 백엔드(Spring WebFlux)와 AI워커(FastAPI RAG)다. F-APP-*(Android)·F-WCON-*/F-WADM-*의 **화면**은 FrontEnd 저장소 소관이라 여기서는 ⬜/🟡로 둔다. 다만 그 화면이 호출할 **API가 준비됐는지**를 "API 근거" 열에 밝혀, UI만 붙이면 되는 것과 서버 작업이 남은 것을 구분한다.

## 결정사항·미정사항 반영

정의서의 확정 12/미정 31 항목 중 서버 설계에 직접 영향을 준 것:

- **원문 서류 업로드 없음 / 합격 예측 없음 / 근거 없는 단정 없음** → 서버 전반에 불변식으로 내장(진단은 후보·준비도·근거만 제시, 등급 미확인 시 전문가 확인으로 안내).
- **전기방석 인증 등급 미확정** → 룰셋이 등급을 단정하지 않고 `flagExpertReview`로 안내(이슈 #23, 공식 확인 후 확정).
- **전기방석 필수 입력항목·모름 처리 방식** → 구현 진행하며 확정 예정(이슈 등록).
- **결정론(Rule) vs 생성(LLM)** → ADR-0003. 판정은 Rule, 문장화만 LLM.

## 갱신 이력

- 초판: F-AUTH(구글 OAuth 포함)·F-APP 입력 API·F-BE 진단/RAG 매핑 반영.
- F-APP-014~018(전기방석 상세 입력) API 근거 갱신.
- 관리자 룰셋 관리 API 반영 → F-WADM-009/010 ✅, F-WCON-004 근거 갱신.
- 관리자 질문(입력 스키마) 관리 API 반영 → F-WADM-006~008 ✅(프레젠테이션 편집), F-WADM-005 🟡.
  단, **새 질문 추가는 코드 계약**(코드·타입·Attribute·룰)이 필요해 API 편집 범위 밖임을 명시.
- 가중치 편집(F-WADM-011)·공식 문서 메타데이터(F-WADM-012/013) 관리 API 반영.
- 감사 로그(F-BE-018 기록 + F-WADM-018 조회) 반영.
- 사용자 목록(F-WADM-002)·CONSULTANT 역할·컨설턴트 승인(F-WADM-003)·대시보드(F-WADM-001) 반영.
- 리포트 문구(F-WADM-016) 반영.
- 컨설턴트 상담 워크플로(F-WCON-002/003/005/006/007/010, F-WADM-017) 반영 — 접수→배정→진행→완료 상태기계.
- 상담 메시지 스레드(F-WCON-008/009/011) 반영 — 컨설턴트 작성 + 소공인 공개 조회(리드 id 접근키).
- 상담 리드 소유자 연결(V16) + 내 상담 조회(F-APP-041 API).
- 알림(F-BE-013, F-APP-045 API) 반영 — 소유자 연결 위에 상담 처리 이벤트 알림 발행·조회·읽음.
- 계정 탈퇴(F-AUTH-018), 컨설턴트 룰조회(F-WCON-004), RAG 검증(F-WADM-015), AI 폴백 설정(F-WADM-020) 반영.
- 전기방석 입력항목(신체접촉 방식·온도조절기 모름·온도정보 출처·자동꺼짐 시간) 변경 반영 — F-APP-014/016/017, F-WADM-008/009/010, F-BE-002/005/010 구현 필요 확인(2026-07-25, 이슈 등록 예정).
- **전기방석 입력 모델 정밀화 구현 완료(2026-07-25)** — BodyContactType(4값)·ControllerStatus(있음/없음/모름)+조절단계·TemperatureSource(측정/추정/모름)·자동꺼짐 시간. 도메인·룰(Attribute·codec)·웹·영속성(V19)·스키마·시드 룰·테스트 전 계층 반영. 신체접촉은 IN[접촉유형]으로 표현(비접촉·비발열 제외). → F-APP-014/016/017 API, F-WADM-008/009/010, F-BE-002/005/010 ✅.
- **백엔드 기존 기능은 대부분 완료.** 남은 부분구현/미구현의 성격:
  - F-WADM-005: 제품군 집합이 룰·타입 계약과 결합된 enum이라 설계상 코드 관리(질문·룰·조회는 API화됨).
  - F-BE-014 ✅: 연락처 AES-GCM 암호화에 더해 보존정책(종착 리드 180일 후 파기, 설정 가능) 구현. F-BE-015 로그 마스킹도 적용됨.
  - F-BE-019: 백엔드 `Dockerfile` 추가로 컨테이너화 완료. 남은 VM 배포는 인프라(이슈 #9). F-AUTH-008: 약관 동의 ✅.
  - 나머지 ⬜는 대부분 Android/Web **화면**(FrontEnd 저장소) — 호출할 API는 "API 근거" 열 참고.
- **개인정보 보존정책·전역 시퀀스 키 전환(2026-07-25)** — 키를 UUID→전역 시퀀스(bigint)로 전환, 보존 기간 경과 리드 자동 파기(F-BE-014) 추가.
