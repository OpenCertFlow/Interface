# 시연 전 점검표

본선 시연 직전에 이 순서대로 확인한다. **조용히 망가지는 것**들을 잡는 것이 목적이다 —
화면은 정상으로 보이는데 결과가 무의미한 상태가 이 시스템에서 가장 위험하다.

## 0. 가장 먼저 — 검색이 진짜로 도는가

```bash
curl -s localhost:8000/health | jq
```

- [ ] `semanticSearch == true`

`false`면 **해시 임베더로 폴백한 상태**다. 검색은 200을 돌려주고 화면도 정상으로 보이지만
결과가 사실상 무작위다. 원인은 대개 `OPENCERTFLOW_EMBEDDING_PROVIDER`가 기본값(`hash`)인 것이다.

```bash
OPENCERTFLOW_EMBEDDING_PROVIDER=fastembed
```

> 임베딩 모델은 약 2.2GB다. 컨테이너 이미지에 굽거나 `OPENCERTFLOW_EMBEDDING_CACHE_DIR`로
> 영속 볼륨을 지정하지 않으면 재시작마다 다시 받는다. 시연 당일 네트워크에 의존하지 않는다.

## 1. 제품군별로 근거가 실제로 나오는가

두 제품군 각각 진단을 한 건씩 실행하고 응답을 확인한다.

- [ ] 모발건조기 — `evidences` 배열이 비어 있지 않다
- [ ] 전기방석 — `evidences` 배열이 비어 있지 않다
- [ ] 두 건 모두 `degraded.evidence == false`

**근거가 0건이면 `degraded.evidence`가 `true`로 나온다.** 이건 버그가 아니라 설계다 —
근거를 붙이지 못했다는 사실을 숨기지 않는다. 다만 시연에서 이 상태가 뜨면
해당 제품군 문서가 색인되지 않은 것이므로 `ai-worker/ingest/corpus/README.md`를 따라 색인한다.

```bash
OPENCERTFLOW_EMBEDDING_PROVIDER=fastembed \
  python -m ingest.ingest ingest/corpus/electric-heating-pad.json --recreate --strict
```

- [ ] `--strict` 색인이 경고 없이 끝난다 (루트 URL 문서가 없다)

## 2. 근거 링크가 실제로 열리는가

리포트의 `evidences[].sourceUrl`을 **직접 눌러 본다.**

- [ ] 사이트 홈이 아니라 그 문단이 있는 페이지가 열린다

심사위원이 가장 쉽게 확인할 수 있는 지점이고, 여기서 홈으로 튀면 "공식 근거"라는 주장 전체가
흔들린다.

## 3. 장애 폴백이 실제로 도는가

관리자 API로 AI를 끄고 진단을 실행한다.

```bash
curl -X PUT localhost:8080/api/v1/admin/ai-fallback \
  -H 'Authorization: Bearer <admin>' -H 'Content-Type: application/json' \
  -d '{"evidenceDisabled": true, "narrationDisabled": true}'
```

- [ ] 진단이 여전히 성공한다 (HTTP 200)
- [ ] `candidates`와 `score`가 유효하다
- [ ] `degraded.evidence == true`, `degraded.narration == true`
- [ ] Web 상담 상세에 "제한된 상태로 생성된 리포트입니다" 안내가 뜬다
- [ ] **시연 후 다시 끈다** (`false`로 원복)

## 4. 두 제품군 종단 흐름

- [ ] 모발건조기: 제품 선택 → 입력 → 진단 → 결과 → 상담 신청
- [ ] 전기방석: 제품 선택 → 입력 → 진단 → 결과 → 상담 신청
- [ ] Web: 상담 목록 → 상세 → 진단 결과·근거·Rule 확인 → 담당 배정 → 상태 변경
- [ ] 내부 메모가 소공인 화면에 보이지 않는다

## 5. 고정 평가데이터

```bash
./gradlew test --tests '*FixedEvaluationDataTest'
```

- [ ] 전 케이스 통과 (정상·모름·미확인·모순·근거부족·AI 장애·권한오류)

## 6. 표현 점검 — 하지 않기로 한 말

화면과 발표 자료를 훑으며 아래 표현이 없는지 본다.

- [ ] "자동 인증 판정" 없음
- [ ] "합격 예측" · "합격 가능성" 없음
- [ ] "공식 문서 자동 업데이트 완료" 없음
- [ ] 준비도 옆에 "인증 합격 확률이 아님" 고지가 보인다
- [ ] 특정 AI 벤더명·모델명이 화면·발표자료·코드 공유 화면에 노출되지 않는다

> `ai-worker/app/config.py`의 `llm_model` 기본값에 모델명이 하드코딩되어 있다.
> 화면 공유나 코드 리뷰에서 노출되므로 발표 전 환경변수 주입으로 정리한다.

## 7. 개인정보

- [ ] 시연 데이터가 전부 가상이다 (실제 연락처·이메일 없음)
- [ ] 로그에 이메일·휴대폰이 마스킹되어 찍힌다
- [ ] 스크린샷·발표자료에 실제 개인정보가 없다

## 8. 환경변수 최종 확인

| 변수 | 확인 |
| --- | --- |
| `OPENCERTFLOW_EMBEDDING_PROVIDER` | `fastembed` — 기본값 `hash`면 검색 무의미 |
| `OPENCERTFLOW_EMBEDDING_CACHE_DIR` | 영속 볼륨 경로 — 없으면 재시작마다 2.2GB 재다운로드 |
| `OPENCERTFLOW_QDRANT_URL` | Qdrant 주소 |
| `OPENCERTFLOW_LLM_ENABLED` | 시연 구성에 맞게 |
| `NEXT_PUBLIC_API_BASE_URL` (Web) | 백엔드 주소. 기본 `http://localhost:8080` |
| DB 접속·JWT 시크릿 | 시크릿 관리 방식으로 주입, 코드·문서에 없음 |

## 9. 복구 계획

시연 중 실패해도 진행할 수 있어야 한다.

- [ ] 로컬 대체 환경이 준비되어 있다
- [ ] AI 워커가 죽어도 진단이 도는 것을 미리 확인했다(3번)
- [ ] 사전 녹화한 시연 영상이 있다
- [ ] "왜 근거가 비었는가"에 답할 수 있다 — `degraded` 플래그와 색인 상태로 설명한다
