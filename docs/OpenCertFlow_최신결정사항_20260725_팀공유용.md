## 3. MVP 제품군 결정

MVP 제품군은 다음 두 종으로 확정한다.

1. 모발건조기
2. 일반 보온용 전기방석

### 3.1 모발건조기

- 첫 번째 기준 제품
- 예선 기획과 현재 Backend Rule 구조의 연속성을 유지
- 비교적 안정적인 기본 진단·결과·컨설팅 흐름을 시연
- 전기방석 변경으로 기존 모발건조기 결과가 변하지 않도록 회귀 테스트

### 3.2 일반 보온용 전기방석

- 두 번째 기준 제품
- 봉제·생활소품 소공인이 방석에 열선·온도조절기·어댑터를 결합한 제조 상황을 대표
- 소공인 타깃성과 제품별 조건 분기를 강화
- 치료·통증 완화 등 의료적 표현은 전문가 확인사항으로 전환
- 의료기기 해당 여부와 안전 적합·부적합을 서비스가 직접 판정하지 않음

LED 조명과 그 밖의 제품군은 현재 MVP에서 제외한다.

## 4. 핵심 서비스 흐름 결정

1. 사용자가 제품군을 선택한다.
2. 제품별 속성과 자료 보유 여부를 입력한다.
3. Rule Engine이 인증 검토 후보와 필수 확인 항목을 식별한다.
4. RAG가 KC 관련 공식 문서에서 적용 가능한 근거를 검색한다.
5. 시스템이 준비도, 누락자료, 표시사항, 리스크와 전문가 확인사항을 정리한다.
6. LLM이 선정된 공식 근거를 바탕으로 설명문을 생성한다.
7. 사용자가 결과와 원문 근거를 확인하고 컨설팅을 신청한다.
8. 컨설턴트가 Web에서 진단 결과·Rule·근거를 검토하고 상담을 처리한다.

모발건조기와 전기방석 모두 제품 선택부터 컨설팅 신청까지 전체 흐름이 완료되어야 한다.

## 8. Rule Engine·RAG·LLM 역할 결정

| 구성 | 책임 |
|---|---|
| Rule Engine | 제품 입력을 기준으로 인증 검토 후보, 구조화된 확인 항목, 누락자료와 전문가 확인 플래그 생성 |
| RAG | 제품군·후보·조건에 맞는 KC 공식 문서 청크 검색 및 근거 후보 제공 |
| 근거 검증 | 출처, 적용 제품, 기준일, 관련성과 중복을 검토해 사용할 근거 선택 |
| LLM | 선택된 근거와 Rule 결과를 사용자 친화적인 설명으로 문장화 |
| Backend | Rule·근거·준비도·리포트·버전 스냅샷 통합 및 저장 |

LLM은 인증 유형이나 최종 판정을 임의 생성하지 않는다. 근거가 부족하면 ‘확인 필요’ 또는 근거 부족 상태를 반환한다.

## 9. 준비도 결정

- 준비도는 공식 요구자료 대비 현재 준비 수준을 보여주는 지표
- 인증 합격 확률이 아님
- 제품별 질문과 평가항목을 분리
- 누락자료와 미확인 정보는 보완 우선순위와 상담 질문에 반영
- Rule·질문·가중치 버전을 결과와 함께 추적
- 전기방석의 신체접촉, 온도조절기, 최고 표면온도와 보호기능 관련 신규 항목을 평가 기준에 반영
- 가중치와 상세 점수 기준은 최신 정의서·관리 기준과 팀 합의에 따름

---

## 10. 공식 문서·데이터 결정

공식 근거 자료는 국가기술표준원, 제품안전 관련 공식 기관과 시험·인증기관의 공개 자료를 우선한다.

공식 문서에는 가능한 범위에서 다음 메타데이터를 관리한다.

- 발행기관
- 문서명
- 적용 제품군
- 제도·인증 유형
- 대상 조건
- 제출자료
- 표시·라벨링
- 예외·확인 필요 조건
- 발행일·확인일·기준일 또는 버전
- 원문 URL
- 정제·색인 상태

Vector DB는 Qdrant를 사용한다. 다른 제품군 전용 문서가 현재 제품의 우선 근거로 선택되지 않도록 제품군과 제도 태그를 검증한다.

공식 자료를 ‘자동으로 항상 최신 상태로 갱신한다’고 표현하지 않는다. 자료의 확인일·버전·적용 기준을 기록하고 팀이 검토한 자료를 반영한다.

## 11. AI 장애·폴백 결정

- AI/RAG Worker 장애가 전체 진단 실패로 이어지지 않도록 구성
- Rule Engine 결과와 구조화된 기본 결과는 유지
- 근거 설명은 승인된 템플릿으로 대체
- 사용자에게 근거 설명이 제한된 상태임을 안내
- 장애 중 LLM의 임의 답변 생성 금지
- RAG·LLM 타임아웃과 폴백을 통합 테스트에 포함

반드시 다음 내용을 유지한다.

- 최종 인증 판정 서비스가 아님
- 안전 적합·부적합을 직접 판정하지 않음
- 준비도 점수는 인증 합격 확률이 아님
- 실제 시험기관의 시험·심사 결과를 대체하지 않음
- 법률 자문이나 인증 대행을 대체하지 않음
- 의료기기 해당 여부를 직접 판정하지 않음
- 근거가 부족한 내용은 추측하지 않음
- 발표와 화면에서 ‘자동 인증 판정’, ‘합격 예측’, ‘공식 문서 자동 업데이트 완료’로 오해될 표현을 사용하지 않음

## 15. 현재 구현 영향과 우선 확인사항

최신 정의서 변경에 따라 다음 항목을 우선 확인한다.

### 전기방석

- Android 질문 UI에 신체접촉, 온도조절기 있음·없음·모름, 최고 표면온도와 출처 반영
- 요청 DTO·Mapper·제품 프로필·진단 스냅샷에 신규 필드 반영
- Rule에서 일반 보온용, 의료적 표현, 접촉 방식, 온도제어, 표면온도, 보호기능과 세탁 구조 사용
- 준비도 평가코드와 가중치 반영
- 정상·모름·미확인·모순 입력 테스트 추가

- 변경 전
- 변경 후
- 변경 사유

  - Android
  - Web
  - Backend
  - AI·데이터

## 18. 팀 확인이 필요한 미정사항

| 항목 | 현재 상태 | 확정 전 주의사항 |
|---|---|---|
| Android Kakao 로그인 구현 방식 | 기술 합의 필요 | SDK·OAuth 흐름과 Backend 검증 계약을 함께 확정 |
| Kakao 토큰 전달 형식 | 기술 합의 필요 | 원본 토큰 노출·로그 저장 금지 |
| 디바이스별 세션 구현 | 기술 합의 필요 | 웹·앱 동시 로그인을 유지하면서 개별 폐기 가능해야 함 |
| 비밀번호 재설정 딥링크 | 기술 합의 필요 | 기본은 Web 완료, 앱 복귀 범위만 확정 |
| 컨설턴트·관리자 Web 저장소 구조 | 담당 협의 필요 | 공통 UI·권한·배포 방식을 고려해 결정 |
| Android·Web 세부 담당 | 담당 협의 필요 | API 계약과 통합 일정에 맞춰 배정 |
| 전기방석 신규 필드명·코드 | 최신 정의서 기준 확인 필요 | Android·Backend·Rule·QA가 동일 계약 사용 |
| 전기방석 준비도 가중치 | 팀 검토 필요 | 합격 확률로 해석되지 않도록 기준 명시 |
| Qdrant 배포·인프라 설정 | 인프라 협의 필요 | 로컬·통합·배포 환경의 설정값을 분리 |
