## 핵심 원칙 세 가지

기획서의 신뢰성 요구사항을 아키텍처 제약으로 옮기면 다음 세 가지입니다. 모든 설계 판단은 여기서 나옵니다.

**1. 판정은 규칙이 하고, LLM은 문장만 만든다.**
인증 후보 식별과 서류 체크는 Rule Engine이 결정론적으로 수행합니다. LLM은 이미 확정된 결과를 사용자가 읽을 문장으로 옮기는 역할만 맡습니다. 따라서 LLM 호출 실패는 진단 실패가 아니며, 리포트는 템플릿 문장으로 폴백합니다.

**2. 근거 없는 주장은 "전문가 확인 필요"로 격리한다.**
RAG 검색으로 공식 문서 근거를 찾지 못한 항목은 단정하지 않고 별도 목록으로 분리합니다. 도메인 모델에 `ExpertReviewItem`이 1급 개념으로 존재하는 이유입니다.

**3. 같은 입력은 같은 결과를 낸다.**
룰 평가는 순수 함수여야 합니다. 룰셋에 버전을 부여하고 진단 결과에 평가 시점의 룰셋 버전을 함께 저장하여, 재현 가능성과 감사 추적을 확보합니다.

## 구현 범위 (해커톤 본선 기준)

- 제품군: 국내 KC 관련 **소형가전제품군**
- 대표 시나리오: **드라이기류**
- 룰: 공식 문서 기반 샘플 규칙 20~30개
- 파일 업로드 제외 — 보유 서류는 **보유 여부 체크** 방식
