# ADR-0001. 헥사고날 아키텍처 채택 (단일 모듈 + ArchUnit)

- 상태: 채택
- 날짜: 2026-07-10
- 결정자: 백엔드·인프라 (장근창, 오태훈)

## 맥락

인증메이커스의 핵심 자산은 **Rule Engine과 점수 산정 로직**입니다. 이 로직의 정확성이 서비스 신뢰성의 전부이며, 심사에서도 "동일 입력 결과의 일관성"을 성과지표로 검증하겠다고 선언했습니다.

동시에 이 로직 주변은 전부 불안정합니다. RAG 워커 API 형태는 AI 담당자와 협의하며 바뀔 것이고, LLM은 교체될 수 있고, 저장소도 확정적이지 않습니다. 해커톤 일정상 이들이 확정되기를 기다렸다가 룰 로직을 짤 수는 없습니다.

## 결정

**헥사고날 아키텍처**를 채택합니다. 룰 평가와 점수 산정을 프레임워크 의존성이 0인 도메인 계층에 두고, 나머지 전부를 포트 뒤로 밀어냅니다.

물리 분리는 **Gradle 멀티모듈 대신 단일 모듈 + 패키지 분리 + ArchUnit 테스트**로 합니다.

## 근거

**왜 헥사고날인가.** 이 프로젝트에서 헥사고날은 유행이 아니라 일정 관리 도구입니다. AI 워커 API가 확정되지 않아도 `SearchEvidencePort` 인터페이스만 합의하면 백엔드는 스텁으로 진도를 뺄 수 있습니다. 6명이 병렬로 일하는 3주 일정에서 이 디커플링의 값어치가 매핑 코드 작성 비용을 넘습니다.

**왜 단일 모듈인가.** 멀티모듈은 컴파일 타임에 의존 방향을 강제한다는 확실한 이점이 있습니다. 하지만 대가가 있습니다.

- 모듈 경계를 잘못 그으면 재조정 비용이 큰데, 도메인이 아직 유동적입니다.
- `settings.gradle`, 모듈별 `build.gradle`, 테스트 픽스처 공유 설정이 늘어납니다.
- 팀 6명 중 헥사고날 멀티모듈 경험자가 보장되지 않습니다. 빌드가 깨졌을 때 해결할 사람이 한 명뿐이면 그게 병목입니다.

ArchUnit 테스트는 컴파일러만큼 즉각적이지는 않지만, CI에서 확실히 잡습니다. 위반이 머지되지 않는다는 결과는 같습니다. 단, **CI에서 반드시 실행되어야** 이 결정이 성립합니다.

**왜 도메인에 JPA 엔티티를 두지 않는가.** `@Entity`를 도메인에 붙이면 도메인 테스트가 JPA 메타모델을 필요로 하고, 지연 로딩 프록시가 도메인 로직에 새어 들어오며, 스키마 변경이 도메인 모델을 흔듭니다. 매핑 코드를 손으로 쓰는 비용(대략 클래스당 20~30줄)을 지불하고 룰 평가 테스트를 순수 자바로 유지합니다.

## 결과

**얻는 것**

- `RuleEvaluator` 테스트가 스프링 컨텍스트 없이 밀리초 안에 끝납니다. 룰 20~30개 × 예외 입력 조합을 부담 없이 검증할 수 있습니다.
- AI 워커 없이도 백엔드 개발과 데모가 가능합니다 (스텁 어댑터).
- 저장소나 LLM 교체 시 도메인은 손대지 않습니다.

**치르는 것**

- 도메인 ↔ JPA 엔티티 ↔ 웹 DTO 3중 매핑. 컨텍스트당 수백 줄의 지루한 코드가 늘어납니다.
- 신규 참여자가 "이 클래스는 어느 계층인가"를 익히는 데 반나절이 듭니다.
- ArchUnit이 CI에서 빠지면 규율이 즉시 무너집니다.

**완화**

- 매핑은 MapStruct 없이 손으로 씁니다. 애노테이션 프로세서 하나를 아끼고, 매핑 버그를 컴파일러가 아닌 테스트로 잡습니다. 클래스 수가 적어 자동화 이득이 적습니다.
- 패키지 구조를 [02-hexagonal-architecture.md](../02-hexagonal-architecture.md#23-패키지-구조)에 못 박고, `common`에 예시 구현을 먼저 넣어 참고 지점을 만듭니다.

## 대안

**계층형 아키텍처 (controller-service-repository).** 가장 빠르게 시작합니다. 하지만 서비스가 `JpaRepository`와 `WebClient`를 직접 참조하게 되고, 룰 평가 테스트가 스프링 컨텍스트에 묶입니다. 이 프로젝트에서 가장 자주 돌려야 할 테스트가 가장 느려집니다. 기각.

**Gradle 멀티모듈 헥사고날.** 위반이 원천 차단된다는 점에서 더 우월합니다. 프로젝트가 3개월 이상 지속되면 이쪽이 맞습니다. 3주 해커톤에서는 설정 비용이 이득을 초과합니다. **본선 이후 서비스를 지속한다면 재검토 대상**입니다 — 패키지 구조를 모듈 경계와 일치시켜 두었으므로 이관 비용은 낮습니다.
